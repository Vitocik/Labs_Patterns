**Вариант 3** – «Траектория движения».

Разработанная программа моделирует полёт тела, брошенного под углом к горизонту. На основании исходной скорости, угла, начальной высоты и ускорения свободного падения рассчитываются время полёта, максимальная высота, дальность и отдельные точки траектории.

## 1. Архитектура решения

Предметная модель сосредоточена в классе Trajectory. Класс TrajectoryBuilder формирует объект пошагово и выполняет проверку параметров. TrajectoryScenarioDirector хранит несколько типовых сценариев. SimulationSettings содержит единые значения по умолчанию и доступен через единственный экземпляр. Клиентом выступает консольный класс Program.

| **Компонент**              | **Назначение**                                   |
|----------------------------|--------------------------------------------------|
| Trajectory                 | готовая неизменяемая траектория и методы расчёта |
| TrajectoryBuilder          | пошаговая сборка Trajectory и валидация          |
| TrajectoryScenarioDirector | типовые последовательности настройки builder     |
| SimulationSettings         | единый набор параметров по умолчанию             |
| Program                    | демонстрация паттернов и вывод результатов       |

## Ход работы

## 3. Паттерн «Одиночка»

В предметной области есть несколько параметров, которые логически должны иметь единое значение во время расчёта: ускорение свободного падения, стандартная начальная скорость, стандартный угол запуска и шаг моделирования. Размещение этих значений в нескольких классах создало бы риск рассогласования. Поэтому они собраны в SimulationSettings.

Конструктор SimulationSettings является закрытым. Единственная точка доступа – статическое свойство Instance. Внутри используется Lazy\<SimulationSettings\>, благодаря чему объект создаётся только при первом обращении, а инициализация остаётся потокобезопасной.

| **Роль**  | **Элемент**        | **Функция в проекте**                     |
|-----------|--------------------|-------------------------------------------|
| Singleton | SimulationSettings | единый объект с настройками моделирования |
| Instance  | InstanceHolder     | ленивое создание через Lazy\<T\>          |
| Клиент    | TrajectoryBuilder  | получает значения по умолчанию            |
| Клиент    | Program            | проверяет единственность экземпляра       |

![Иллюстрация](Lab1_Trajectory/UML/singleton_final.png)

Таким образом, Singleton не участвует непосредственно в расчёте движения, а обеспечивает единый источник стандартных настроек. Это делает конфигурационную часть программы централизованной и не заставляет передавать одинаковые значения через каждый вызов конструктора.

## 4. Паттерн «Строитель»

Класс Trajectory содержит несколько параметров, которые формируют единый объект: положение старта, начальную скорость, угол, ускорение и шаг времени. Builder позволяет устанавливать эти значения по отдельности и в удобной последовательности.

Каждый метод TrajectoryBuilder возвращает текущий экземпляр строителя, поэтому используется цепочка вызовов. Метод Build() является границей между настройкой и созданием продукта: сначала выполняется валидация, затем вызывается внутренний конструктор Trajectory.

| **Роль** | **Класс**                  | **Ответственность**                       |
|----------|----------------------------|-------------------------------------------|
| Product  | Trajectory                 | неизменяемая модель готовой траектории    |
| Builder  | TrajectoryBuilder          | пошаговая настройка и проверка параметров |
| Director | TrajectoryScenarioDirector | создание заранее определённых сценариев   |
| Client   | Program                    | вызывает builder и использует результат   |

## 5. Математическая модель расчёта

Для каждой траектории начальная скорость раскладывается на составляющие. При постоянном ускорении свободного падения координаты тела определяются следующим образом:

> vₓ = v₀ · cos(α)
>
> vᵧ = v₀ · sin(α)
>
> x(t) = x₀ + vₓ · t
>
> y(t) = y₀ + vᵧ · t − g · t² / 2

Время полёта вычисляется как положительный корень уравнения y(t)=0:

> T = (vᵧ + √(vᵧ² + 2 · g · y₀)) / g

## 7. Валидация и типовые сценарии

Builder не передаёт в программу объект с заведомо неправильными параметрами. Проверяются отрицательная начальная высота, неположительная скорость, недопустимый угол, неположительное ускорение и неверный шаг времени. Обнаруженные ошибки объединяются в TrajectoryValidationException.

```csharp
var errors = new List<string>();
if (_startY < 0)
    errors.Add("Начальная высота не может быть отрицательной.");
if (_initialSpeed <= 0)
    errors.Add("Начальная скорость должна быть больше нуля.");
if (_gravity <= 0)
    errors.Add("Ускорение должно быть больше нуля.");
if (_timeStep <= 0)
    errors.Add("Шаг расчёта должен быть больше нуля.");
if (errors.Count > 0)
    throw new TrajectoryValidationException(errors);
```

## 8. Роль Director и Product

TrajectoryScenarioDirector упрощает демонстрацию повторяющихся конфигураций. В проекте предусмотрены сценарии стандартного броска, запуска с платформы и высокоскоростного движения. Director вызывает последовательность методов Builder, а завершает её тем же Build().

```csharp
_builder.Reset();
_builder.SetStartPosition(0, 5)
    .SetInitialSpeed(18)
    .SetLaunchAngle(35);
return _builder.Build();
```

*Листинг 4 — Типовой сценарий Director*
Класс Trajectory после построения хранит только готовые параметры. Методы GetFlightTime(), GetMaximumHeight(), GetRange() и CalculatePoints() работают исключительно с состоянием готового объекта, то есть ответственность за создание и ответственность за расчёт разделены.

```csharp
public double GetFlightTime()
{
    double vy = GetVerticalSpeed();
    return (vy + Math.Sqrt(vy * vy + 2 * Gravity * StartY)) / Gravity;
}
public double GetMaximumHeight() =>
    StartY + Math.Pow(GetVerticalSpeed(), 2) / (2 * Gravity);
```

## 10. Проверка корректности решения

Для Singleton используется проверка ReferenceEquals(first, second). Ожидаемый результат – true, что демонстрирует единственность экземпляра.

Дополнительно закрытый конструктор исключает создание объекта SimulationSettings напрямую из клиентского кода.

Для Builder проверяется как обычная последовательность вызовов, так и восстановление значений по умолчанию через Reset(). Если передать недопустимые параметры, Build() выбрасывает TrajectoryValidationException с перечнем обнаруженных ошибок.

Корректность математического расчёта проверяется сравнением полученных значений с аналитическими формулами баллистического движения. Набор точек строится от t=0 до точного момента приземления, поэтому последняя точка соответствует y=0 с учётом округления вычислений.

## 11. Преимущества реализации

- централизованные настройки не дублируются по классам;

- создание объекта Trajectory отделено от его внутреннего представления;

- цепочка методов Builder читается как последовательность настройки сценария;

- валидация сосредоточена в одном месте и не позволяет получить некорректный объект.

SimulationSettings обеспечивает единый набор параметров моделирования, а TrajectoryBuilder формирует проверенный объект Trajectory поэтапно. TrajectoryScenarioDirector дополняет Builder готовыми сценариями, не дублируя логику создания.
